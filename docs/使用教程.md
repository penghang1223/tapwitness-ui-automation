# TapWitness（见信）使用教程 — UI 自动化测试工作流

## 从零开发（8 阶段）
1. `/tw:project-scan` 接入项目 → 2. `/tw:new-feature <name>` → 3. `/tw:business-context` 走三道门 …
或用 `/tw:auto <name>` 半自动（阶段 1/3/4/5 暂停）、`/tw:auto-full <name>` 全自动。
`/tw:workflow-status` 看进度，`/tw:workflow-next` 驱动下一步。

## 录制驱动（5 阶段）
已能手工跑通一条流程时：`/tw:record-feature <name>` → `/tw:record-capture`（1e 人工核对）→
`/tw:record-casegen --single` → `/tw:record-dev` → `/tw:record-run` → `/tw:record-review`。
`/tw:record-auto <name>` 半自动；`--full` 全自动（触发 3 类安全阀即停）。

## 辅助
`/tw:dump-page` 抓证据、`/tw:ui-test-diagnosis` 诊断失败、`/tw:feedback` 提交域层坑点、
`/tw:ui-test-extend` 派生新场景、`/tw:env-setup` 环境体检、`/tw:setup-mcp` 移动端 MCP。

## 反馈提交

`/tw:feedback` 先把坑点写入 `.claude/tw_feedback.md`，再调用
`tw/tools/submit_feedback.py --yes` 自动提交为框架仓库的 Issue
（`penghang1223/tapwitness-ui-automation`，标签 `tw-feedback`）。

- 前置：本机安装并登录 `gh`（`gh auth login`）。对公开仓库开 issue 不需要额外权限。
- 提交内容按白名单字段构造并脱敏：绝对路径、URL、邮箱、凭据不会进入公开 Issue。
- 成功：队列状态改为 `已提交(Issue #N,<日期>)`，写入 `.claude/tw_feedback_submitted.json` 去重。
- 失败（未装 gh / 未登录 / 网络）：反馈**保留在本地队列**，脚本打印预填 Issue 链接供人工提交。
- 只想预览：`python3 <插件根>/tw/tools/submit_feedback.py --dry-run`；
  关闭自动提交：把 profile 的 `feedback_channel.auto_submit` 设为 `false`。
- 反馈入口：https://github.com/penghang1223/tapwitness-ui-automation/issues/new?template=tw-feedback.yml
